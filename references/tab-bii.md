# ТАБ:Библиотека искусственного интеллекта (ТАБ:БИИ)

Справочник для разработки: что это, как поставить, какие функции звать и чего избегать.
Источник: «ТАБ БИИ. Описание функций библиотеки», вер. 0.30 от 16.04.2026 (актуальную версию
всегда можно перекачать: `scripts/fetch-tab-bii.py --what doc`).

## Что это

Расширение конфигурации (`.cfe`) с набором функций на встроенном языке 1С, закрывающих типовые
ИИ-задачи: распознавание сканов и фото, работа с текстом и звуком, генерация данных и изображений,
семантический поиск, классификация, поиск аномалий, прогнозирование, прямые промпты в нейросеть
и обучение (RAG).

- Совместимо с платформой **1С:Предприятие 8.3.18+**, с типовыми и самописными конфигурациями,
  с БСП и без неё.
- Само расширение распространяется бесплатно; платная часть — инфраструктура (облако pay-as-you-go
  по символам либо локальный дистрибутив LLM «ТАБ:ЦА»).
- Два режима подключения: **облако** (ключ доступа из личного кабинета) и **локально**
  (свой сервер с ТАБ:ЦА, работает в безопасном режиме).
- В составе есть MCP-сервер (AI-ассистент ⇄ MCP ⇄ OData ⇄ 1С) — для чтения данных базы нейросетью.

## Главное правило разработки

**ИИ-функциональность в 1С делается вызовами функций БИИ, а не своим HTTP-клиентом к LLM.**
Не пиши `HTTPСоединение` к OpenAI/GigaChat/DeepSeek, не изобретай свой формат промптов и парсинг
ответов, не тащи ключи моделей в конфигурацию. Если нужной функции в БИИ нет — бери
`таб_ПрямаяИнтеграцияСНейросетями.СделатьПромптВНейросеть`, это тоже часть библиотеки и оно уже
решает авторизацию, балансировку моделей, биллинг и логирование.

Прикладной код должен зависеть только от общих модулей `таб_*`. Перед вызовом проверяй, что
расширение реально стоит в базе (см. «Проверка наличия БИИ»), и давай понятную ошибку, если нет.

## Установка и настройка

### Автозагрузка дистрибутива

```bash
python3 scripts/fetch-tab-bii.py --dest .tmp/tab-bii     # печатает путь к .cfe
python3 scripts/fetch-tab-bii.py --url-only              # только ссылка, без загрузки
python3 scripts/fetch-tab-bii.py --what doc --dest .tmp  # свежее описание функций (.docx)
```

Скрипт разбирает карточку товара
<https://tab-store.ru/product/blok_ii/tab-biblioteka-iskusstvennogo-intellekta/> и берёт ссылку
по видимой подписи файла: **«ТАБ_БИИ»** — дистрибутив (zip с `.cfe`), **«ТАБ БИИ. Описание функций
библиотеки»** — документация. Прямые ссылки вида `/upload/iblock/<hash>/<hash>.zip` меняются с
каждой публикацией версии, поэтому их нельзя зашивать в код и кэшировать надолго.

Загружай дистрибутив во временный каталог проекта (`.tmp/`, `.gitignore`), а не в репозиторий.

Fallback, если вёрстка страницы поменялась и скрипт не нашёл ссылку:

```bash
curl -sSL -A "Mozilla/5.0" "https://tab-store.ru/product/blok_ii/tab-biblioteka-iskusstvennogo-intellekta/" \
  | grep -oE 'href="/upload/iblock/[^"]+\.(zip|cfe)"'
```

и дальше вручную сопоставить ссылку с подписью на странице.

### Установка расширения

Через конфигуратор: *Конфигурация — Расширения конфигурации* — добавить расширение, оставить
только флажок **«Активно»** (снять «Безопасный режим» и «Защита от опасных действий»),
*Конфигурация — Загрузить конфигурацию из файла…* — выбрать `.cfe` — принять изменения структуры.

Через предприятие (БСП): *Настройка и администрирование — Поддержка и обслуживание — Печатные формы,
отчёты и обработки — Расширения — Добавить из файла*, снять флажок «Безопасный режим», перезапустить.

Пакетно (предпочтительно в вайб-цикле, см. SKILL.md — «1C Command Workflow»):

```bash
ibcmd infobase config extension create --name=таб_БИИ --name-prefix=таб_ --database-path=<...>
ibcmd infobase config load --extension=таб_БИИ --file=<путь к .cfe> --database-path=<...>
ibcmd infobase config apply --extension=таб_БИИ --database-path=<...>
```

Точный набор ключей зависит от версии платформы — сверяйся с `ibcmd help`, а если `ibcmd` не умеет
нужную операцию, используй пакетный `1cv8 DESIGNER /LoadCfg <файл> -Extension <имя>`.

### Подключение

Кнопка **«Настройки»** на форме БИИ, два варианта:

- **В облаке** (по умолчанию). Ключ доступа берётся в личном кабинете. Личный кабинет и оплата
  облачной инфраструктуры: <https://app-519908.1cmycloud.com/applications/ILLM/lk>.
  Там же выбирается модель LLM по умолчанию, вводится e-mail для чека и оплачивается тариф
  (Демо — 10 тыс. символов, Первый — 180 тыс. символов, Расширенный — 450 тыс. символов).
  Логин и ключ доступа переносятся в настройки подключения БИИ, дальше — «Проверить подключение».
  Один личный кабинет можно завести на всю организацию.
- **Локально**. Администратор ставит ТАБ:ЦА (цифровой ассистент — мультиагентная нейросеть +
  балансировщик), в настройках указываются адрес сервера, порт (по умолчанию `1082`),
  пользователь и пароль. Кнопка «Проверить соединение» гоняет полный тест (авторизация, сообщения,
  история, модели, диалоги, обучение).

Никогда не коммить логин/ключ доступа в репозиторий и не подставляй их в примеры кода —
это данные из настроек базы.

### MCP (доступ нейросети к данным 1С)

Нужны платформа 8.3.10+, опубликованная база на веб-сервере и включённый OData. Настройка:
«Настройки подключения ИИ к базе данных 1С (MCP)» → обработка OData → отдельный пользователь для
REST-сервиса → на вкладке «Состав» загрузить метаданные и отметить объекты → в БИИ указать путь
к веб-публикации, логин/пароль → «Зарегистрировать подключение». Для публичных сетей HTTPS обязателен.

## Баланс и лимиты

- `таб_ВспомогательныеФункции.ПроверитьБалансИАвторизацию()` → `Структура(Баланс, ИдПользователя, Ошибки)`.
  `Ошибки` — пустая строка, если всё в порядке. `Баланс` — остаток в символах.
  **Вызывай её перед массовыми/фоновыми прогонами** и останавливай обработку, если баланс мал или
  авторизация не прошла: иначе фоновое задание молча сожжёт остаток и упадёт на середине.
- Точное имя модуля вспомогательных функций сверь в конфигураторе: в документации оно напечатано
  с пробелом («таб_Вспомогательные Функции»), что для имени общего модуля невозможно.
- Расход считается в символах, поэтому длинные промпты и большие списки полей стоят денег.
  Для регламентных заданий закладывай ограничение количества объектов за прогон.
- Изображения/документы: **не более 4 МБ**, форматы `jpg`/`pdf` (у части функций также `png`,
  `webp`, `docx` — смотри конкретную функцию). Проверяй размер до вызова.
- Отчёт «Динамика использования нейросети» в БИИ — для прогноза пополнения баланса.

## Синхронно или асинхронно

- **Синхронный** вызов блокирует сеанс до ответа модели. Это норма для серверного кода:
  регламентных и фоновых заданий, обработчиков очередей — там некому «подвисать».
  В управляемых формах с БСП синхронный вызов заворачивай в штатные длительные операции
  (`ДлительныеОперации.ВыполнитьВФоне`).
- **Асинхронный** (`...Асинх`) — для обычных форм и платформ без БСП, где нет штатной асинхронности.
  Требует `Источник` (ссылка/идентификатор формы/UUID) и `Обработчик`: имя экспортной функции
  общего модуля («`таб_ОбщиеФункцииБИИ.ВыполнитьОбработчикРезультата`»), модуля менеджера
  («`Справочники.Номенклатура.ВыполнитьОбработчикРезультата`»), метода модуля объекта
  («`ВыполнитьОбработчикРезультата`») либо `ОписаниеОповещения` на клиенте.

Правило для этого скила: **в регламентных и фоновых заданиях — синхронные функции**,
асинхронные — только когда явно нужен коллбэк в интерфейс.

| Функция | Синтаксис | Возврат |
|---------|-----------|---------|
| `ОпределитьЗначимыеРеквизитыДокумента` | `(Документ, СписокПолей)` | `СписокЗначений`: ключи = переданные поля |
| `ОпределитьЗначимыеРеквизитыДокументаАсинх` | `(Документ, СписокПолей, Источник, Обработчик)` | то же, через обработчик |

| `РаспознатьВесьТекстСДокументаАсинх` | `(Документ, Источник, Обработчик)` | `Строка` |
| `ПроверитьНаличиеПодписиИПечатиНаДокументе` | `(Знач Документ)` | `Структура`: `ПечатиКонтрагентов` (массив структур с `НаименованиеКонтрагента`, `ИНН`, `Роль`, `КоличествоПечатей`, `КоличествоПодписей`), `НераспознанныеПечати`, `НераспознанныеПодписи`, `ВсегоПечатей`, `ВсегоПодписей` |
| `ПроверитьНаличиеПодписиИПечатиНаДокументеАсинх` | `(Знач Документ, Знач Источник, Обработчик = "")` | `Структура(Подписей, Печатей)` |
| `ПроверитьСоответствиеПодписиИПечатиОбразцам` | `(Знач Документ, Знач ОбразецПодписи = Неопределено, Знач ОбразецПечати = Неопределено)` | `Структура` с процентами соответствия |
| `ЗаполнитьОбъектПоДаннымДокумента` | `(Документ, Объект)` | заполненный объект (записать самому) |
| `СоздатьОбъектыПоДаннымДокументовПакетно` | `(ПакетДокументов, ТипОбъекта, Источник, Обработчик)` | `СписокЗначений` ссылок на созданные объекты |
| `НайтиНарущенияВнутреннегоИВнешнегоЗаконодателстваПоФото` *(в разработке)* | `(Знач Документ)` | `Массив` нарушений (`ОписаниеНарушения`, `ТипИсточника`, `ТипНормоакта`, `НомерНормативногоАкта`, `ОбоснованиеИзКонтекста`, `ТребуетПроверки`, `УверенностьПривязки`) |

`ОпределитьЗначимыеРеквизитыДокумента` — **основная функция «определить содержание по скану/фото»**:
распознаёт содержимое, классифицирует и возвращает его в виде переданной структуры полей.
Возвращает только базовые типы (строка, число, булево, дата); поиск ссылочных объектов — это
`таб_ПоискИнформации.НайтиПоСмыслу`.

`Документ` во всех функциях — `ДвоичныеДанные` (у части функций допустим адрес временного хранилища).

### Классификация — `таб_КлассификацияИКластеризация`

| Функция | Синтаксис | Возврат |
|---------|-----------|---------|
| `ОпределитьКатегориюПоДанным` | `(ОписаниеДанных, СписокКатегорий, СистемныйПромт)` | `Строка` — одна категория из списка |
| `ОпределитьКатегориюПоДаннымПауза` | `(ОписаниеДанных, СписокКатегорий, СистемныйПромт)` | то же, вариант с паузой — для потоковых прогонов |

Это самый надёжный способ получить от модели **детерминированный ответ из закрытого списка**
вместо свободного текста: сравнение «совпало / не совпало», разбор обращений, автопростановка
вида номенклатуры. Чем подробнее `ОписаниеДанных`, тем лучше классификация.

### Генерация — `таб_ГенерацияДанных`

| Функция | Синтаксис | Возврат |
|---------|-----------|---------|
| `СоздатьОписаниеКОбъекту` | `(Объект, ВидОписания, Контекст)` — вид: «маркетинговое» / «вежливое» | `Строка` |
| `СоздатьДемоДанные` | `(СписокОбъектов, КоличествоОбъектов, ОписаниеХарактераДанных = "")` | `Массив` созданных объектов |
| `СгенерироватьРисунок` | `(ОписаниеРисунка, Модель, КоличествоРисунков, Источник, Обработчик)` | `СписокЗначений` |
| `ВыполнитьЮнитТестПоТекстуФункции` *(в разработке)* | `(ИмяИПараметрыФункции)` | `ТаблицаЗначений` ошибок |

`СгенерироватьРисунок`: модели «Взгляд» (креативнее, всегда 4 рисунка) и «Мастер» (точнее, 1–4);
параметры прямо в строке описания — `::сср 16:9`, `::креатив больше`, `::убрать лес`.
Локально требует отдельного сервера с «ТАБ:Нейросеть АРТ».

связывание объектов при загрузке данных.

### Прямые промпты — `таб_ПрямаяИнтеграцияСНейросетями`

| Функция | Синтаксис |
|---------|-----------|
| `СделатьПромптВНейросеть` | `(ТекстПромпта, СистемныйПромпт)` — без данных обучения |
| `СделатьПромптВНейросетьАсинх` | `(ТекстПромпта, Документ, Модель, Организация, Источник, Обработчик)` — с учётом обучения |

Системный промпт задаёт роль и рамки («Ты бухгалтер, для тебя важен учёт с уровнем ошибок
не более 5% от валюты баланса»). Асинхронный вариант умеет принимать документ и конкретную модель;
`Организация` — код ассистента, в разрезе которого проводилось обучение.

### Обучение — `таб_ОбучениеНейросети`

`ОбучитьНейросетьДаннымиФайлов`, `ОбучитьНейросетьДаннымиТаблицыЗначений`,
`ПолучитьСписокПроведенныхОбучений`, `ОчиститьРанееПроведенноеОбучение`.

## Проверка наличия БИИ из кода

Не полагайся на то, что расширение стоит. Перед первым вызовом:

```bsl
Функция БИИДоступна(ТекстОшибки) Экспорт
	ТекстОшибки = "";
	Если Метаданные.ОбщиеМодули.Найти("таб_КомпьютерноеЗрениеИзвлечениеИнформации") = Неопределено Тогда
		ТекстОшибки = "Не установлено расширение ТАБ:Библиотека искусственного интеллекта.";
		Возврат Ложь;
	КонецЕсли;
	Возврат Истина;
КонецФункции
```

Вызов функции расширения из кода конфигурации (когда прикладной код живёт не в самом БИИ) делай
через `ОбщегоНазначения.ОбщийМодуль("таб_...")` (БСП) или `Вычислить`, чтобы конфигурация
компилировалась и без расширения — и обязательно с проверкой выше.

## Ошибки и устойчивость

- Любой вызов LLM может упасть по сети, таймауту, балансу или вернуть неожиданный текст.
  Оборачивай в `Попытка … Исключение`, пиши в журнал регистрации, не роняй весь прогон из-за
  одного объекта.
- Ответ модели — данные, а не команда. Никогда не подставляй его в `Выполнить`/`Вычислить`,
  в динамический запрос или в путь к файлу.
- Для повторяемости логируй, что именно уходило в модель и что вернулось (по объекту),
  иначе разбирать расхождения будет нечем.
- Идемпотентность: результат проверки сохраняй в регистр сведений с хэшем исходного файла,
  чтобы повторный прогон не тратил баланс на то же самое и не плодил дубли задач.
