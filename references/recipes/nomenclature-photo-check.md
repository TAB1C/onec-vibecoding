# Рецепт: регламентная проверка наименований номенклатуры по фото

Постановка: **«Сделай регламентное задание по проверке названий номенклатуры к фото; если есть
разница — сгенерировать задачу на администратора».**

Решение целиком строится на ТАБ:БИИ: содержание фото определяется функцией распознавания
скана/фото, сравнение наименования с распознанным содержанием — функцией категоризации.
Своих обращений к LLM в коде нет.

Дальше — рабочий каркас. Имена объектов конфигурации (номенклатура, файлы, задачи, пользователи)
в разных конфигурациях отличаются, поэтому шаг «Разведка» обязателен: не подставляй код вслепую.

## 1. Разведка в конкретной базе

Ответь на четыре вопроса — от них зависит код:

1. **Где лежит фото номенклатуры?** Типовые варианты:
   - реквизит-`ХранилищеЗначения` в самом справочнике (самописные конфигурации);
   - присоединённые файлы: `Справочники.НоменклатураПрисоединенныеФайлы` + реквизит
     `ОсновноеИзображение` у номенклатуры (УТ, ERP, КА);
   - БСП: данные файла через `РаботаСФайлами`/`ПрисоединенныеФайлы`, физически —
     в регистре двоичных данных или в томе хранения файлов.
2. **Есть ли подсистема БСП «Бизнес-процессы и задачи»?** Проверь наличие
   `БизнесПроцессы.Задание` и `Задачи.ЗадачаИсполнителя`. Если их нет — задачи придётся
   заводить своим объектом.
3. **Кто «администратор»?** Конкретный пользователь, роль исполнителя или группа —
   уточни у заказчика и вынеси в настройку, а не в код.
4. **Стоит ли БИИ и настроено ли подключение?** `Метаданные.ОбщиеМодули.Найти("таб_КомпьютерноеЗрениеИзвлечениеИнформации")`
   и `ПроверитьБалансИАвторизацию()` — до всякой разработки.

Команды разведки (навыки поставщика, см. `references/vendor-skills.md`):

```bash
/meta-info Справочники.Номенклатура        # реквизиты, где картинка
/meta-info БизнесПроцессы.Задание          # состав реквизитов задачи
rg -l "ПолучитьДвоичныеДанныеФайла|ПрисоединенныеФайлы" src/
```

## 2. Состав решения

Всё делается в **отдельном расширении** (или в уже существующем расширении проекта),
не в конфигурации поставщика. Префикс ниже — `пфн_`, замени на префикс своего расширения.

| Объект | Вид | Назначение |
|--------|-----|-----------|
| `пфн_ПроверкаФотоНоменклатурыСервер` | Общий модуль (сервер) | вся логика |
| `пфн_ПроверкаНаименованийНоменклатурыПоФото` | Регламентное задание | точка входа по расписанию |
| `пфн_РезультатыПроверкиФотоНоменклатуры` | Регистр сведений | результат + хэш фото (идемпотентность) |
| `пфн_АдминистраторДляЗадач` | Константа | кому ставить задачу |
| `пфн_МаксимумПроверокЗаПрогон` | Константа | ограничение расхода баланса |
| `пфн_МинимальныйБалансСимволов` | Константа | порог остановки прогона |

Регистр обязателен: без него каждый прогон будет заново гонять все фото через модель (деньги)
и плодить дубли задач по одной и той же номенклатуре.

## 3. Генерация метаданных

JSON для `/meta-compile` (синтаксис — `docs/meta-dsl-spec.md` у поставщика):

```json
[
  {
    "type": "CommonModule",
    "name": "пфн_ПроверкаФотоНоменклатурыСервер",
    "context": "server"
  },
  {
    "type": "ScheduledJob",
    "name": "пфн_ПроверкаНаименованийНоменклатурыПоФото",
    "synonym": "Проверка наименований номенклатуры по фото",
    "methodName": "пфн_ПроверкаФотоНоменклатурыСервер.ВыполнитьПроверку",
    "key": "ПроверкаФотоНоменклатуры",
    "predefined": true,
    "use": false,
    "restartCountOnFailure": 3,
    "restartIntervalOnFailure": 60
  },
  {
    "type": "InformationRegister",
    "name": "пфн_РезультатыПроверкиФотоНоменклатуры",
    "synonym": "Результаты проверки фото номенклатуры",
    "dimensions": ["Номенклатура: CatalogRef.Номенклатура"],
    "resources": [
      "ХэшФото: String(32)",
      "НаименованиеНаМоментПроверки: String(150)",
      "ДатаПроверки: DateTime",
      "Статус: String(30)",
      "ОписаниеПоФото: String(500)",
      "Расхождение: String(1000)"
    ]
  },
  { "type": "Constant", "name": "пфн_АдминистраторДляЗадач", "valueType": "CatalogRef.Пользователи" },
  { "type": "Constant", "name": "пфн_МаксимумПроверокЗаПрогон", "valueType": "Number(5,0)" },
  { "type": "Constant", "name": "пфн_МинимальныйБалансСимволов", "valueType": "Number(10,0)" }
]
```

```bash
/meta-compile spec.json src/extension     # генерация XML
/meta-validate src/extension              # проверка перед загрузкой
```

`use: false` — намеренно: включать задание по расписанию нужно осознанно, после того как
проверка отработала вручную и настроен исполнитель задач.

Ссылку на задачу в регистре сведений не храним отдельным ресурсом, чтобы регистр не зависел от
того, каким объектом реализованы задачи в конкретной конфигурации: связь ищется по номенклатуре
через предмет задачи. Если в базе есть `БизнесПроцессы.Задание` — можно добавить ресурс
`"Задача: BusinessProcessRef.Задание"` и хранить ссылку явно.

## 4. Код общего модуля

```bsl
#Область ПрограммныйИнтерфейс

// Точка входа регламентного задания.
Процедура ВыполнитьПроверку() Экспорт
	
	ОбщегоНазначения.ПриНачалеВыполненияРегламентногоЗадания(
		Метаданные.РегламентныеЗадания.пфн_ПроверкаНаименованийНоменклатурыПоФото);
	
	ТекстОшибки = "";
	Если Не БИИДоступна(ТекстОшибки) Тогда
		ЗаписатьВЖурнал(ТекстОшибки, УровеньЖурналаРегистрации.Ошибка);
		Возврат;
	КонецЕсли;
	
	Администратор = Константы.пфн_АдминистраторДляЗадач.Получить();
	Если Не ЗначениеЗаполнено(Администратор) Тогда
		ЗаписатьВЖурнал(
			"Не заполнена константа ""Администратор для задач"" — некому ставить задачи. Проверка не выполнялась.",
			УровеньЖурналаРегистрации.Ошибка);
		Возврат;
	КонецЕсли;
	
	Если Не БалансДостаточен(Администратор) Тогда
		Возврат;
	КонецЕсли;
	
	Кандидаты = КандидатыНаПроверку();
	Проверено = 0;
	Расхождений = 0;
	
	Для Каждого Кандидат Из Кандидаты Цикл
		Попытка
			Если ПроверитьНоменклатуру(Кандидат, Администратор) Тогда
				Расхождений = Расхождений + 1;
			КонецЕсли;
			Проверено = Проверено + 1;
		Исключение
			// Одна проблемная позиция не должна ронять весь прогон.
			ЗаписатьВЖурнал(СтрШаблон("Номенклатура %1: %2",
				Кандидат.Номенклатура, ПодробноеПредставлениеОшибки(ИнформацияОбОшибке())),
				УровеньЖурналаРегистрации.Ошибка);
		КонецПопытки;
	КонецЦикла;
	
	ЗаписатьВЖурнал(СтрШаблон("Проверено позиций: %1, расхождений: %2.", Проверено, Расхождений));
	
КонецПроцедуры

#КонецОбласти

#Область СлужебныеПроцедурыИФункции

// Порция номенклатуры к проверке: с фото, ещё не проверенная или изменившаяся с прошлой проверки.
Функция КандидатыНаПроверку()
	
	МаксимумЗаПрогон = Константы.пфн_МаксимумПроверокЗаПрогон.Получить();
	Если Не ЗначениеЗаполнено(МаксимумЗаПрогон) Тогда
		МаксимумЗаПрогон = 100;
	КонецЕсли;
	
	Запрос = Новый Запрос;
	Запрос.Текст =
	"ВЫБРАТЬ ПЕРВЫЕ &МаксимумЗаПрогон
	|	Номенклатура.Ссылка КАК Номенклатура,
	|	Номенклатура.Наименование КАК Наименование,
	|	Номенклатура.Артикул КАК Артикул,
	|	Результаты.ХэшФото КАК ХэшФото,
	|	Результаты.НаименованиеНаМоментПроверки КАК НаименованиеНаМоментПроверки
	|ИЗ
	|	Справочник.Номенклатура КАК Номенклатура
	|		ЛЕВОЕ СОЕДИНЕНИЕ РегистрСведений.пфн_РезультатыПроверкиФотоНоменклатуры КАК Результаты
	|		ПО Результаты.Номенклатура = Номенклатура.Ссылка
	|ГДЕ
	|	НЕ Номенклатура.ЭтоГруппа
	|	И НЕ Номенклатура.ПометкаУдаления
	|	И Номенклатура.ОсновноеИзображение <> ЗНАЧЕНИЕ(Справочник.НоменклатураПрисоединенныеФайлы.ПустаяСсылка)
	|	И (Результаты.ДатаПроверки ЕСТЬ NULL
	|			ИЛИ Результаты.НаименованиеНаМоментПроверки <> Номенклатура.Наименование)
	|УПОРЯДОЧИТЬ ПО
	|	Результаты.ДатаПроверки ВОЗР";
	// ↑ Условие по фото и поле артикула зависят от конфигурации — правь по результатам разведки.
	// Изменение самого файла фото ловится сравнением хэша уже после чтения данных.
	Запрос.УстановитьПараметр("МаксимумЗаПрогон", МаксимумЗаПрогон);
	
	Возврат Запрос.Выполнить().Выгрузить();
	
КонецФункции

// Возвращает Истина, если найдено расхождение.
Функция ПроверитьНоменклатуру(Кандидат, Администратор)
	
	ДанныеФото = ДвоичныеДанныеФото(Кандидат.Номенклатура);
	Если ДанныеФото = Неопределено Тогда
		ЗаписатьРезультат(Кандидат, "", "НетФото", "", "");
		Возврат Ложь;
	КонецЕсли;
	
	// Ограничение БИИ: не более 4 МБ на изображение.
	Если ДанныеФото.Размер() > 4 * 1024 * 1024 Тогда
		ЗаписатьРезультат(Кандидат, "", "ФотоСлишкомБольшое", "", "");
		ЗаписатьВЖурнал(СтрШаблон("Фото %1 больше 4 МБ, пропущено.", Кандидат.Номенклатура),
			УровеньЖурналаРегистрации.Предупреждение);
		Возврат Ложь;
	КонецЕсли;
	
	Хэш = ХэшДанных(ДанныеФото);
	Если Хэш = Кандидат.ХэшФото И Кандидат.НаименованиеНаМоментПроверки = Кандидат.Наименование Тогда
		Возврат Ложь; // Ничего не менялось — не тратим баланс.
	КонецЕсли;
	
	МодульЗрение = ОбщегоНазначения.ОбщийМодуль("таб_КомпьютерноеЗрениеИзвлечениеИнформации");
	
	// Отсекаем мусорные изображения до дорогого разбора.
	ФотоПригодно = МодульЗрение.ОпределитьКорректностьЗагруженныхСканов(
		ДанныеФото,
		"фотография товара, изображение изделия, упаковка товара",
		"пустое изображение, посторонний объект, люди, скан текстового документа");
	
	Если Не ФотоПригодно Тогда
		ЗаписатьРезультат(Кандидат, Хэш, "ФотоНепригодно", "", "Изображение не похоже на фото товара.");
		СоздатьЗадачуАдминистратору(Кандидат.Номенклатура, Администратор,
			"Непригодное фото номенклатуры",
			СтрШаблон("У позиции ""%1"" загружено изображение, не похожее на фото товара. Проверьте и замените фото.",
				Кандидат.Наименование));
		Возврат Истина;
	КонецЕсли;
	
	// Ключевой вызов: определение содержания по фото.
	СписокПолей = Новый СписокЗначений;
	СписокПолей.Добавить("НаименованиеТовара");
	СписокПолей.Добавить("Бренд");
	СписокПолей.Добавить("МодельИлиАртикул");
	СписокПолей.Добавить("ОбъемВесКоличество");
	СписокПолей.Добавить("КатегорияТовара");
	
	РаспознанныеПоля = МодульЗрение.ОпределитьЗначимыеРеквизитыДокумента(ДанныеФото, СписокПолей);
	ОписаниеПоФото = ПредставлениеРаспознанного(РаспознанныеПоля);
	
	Если Не ЗначениеЗаполнено(ОписаниеПоФото) Тогда
		ЗаписатьРезультат(Кандидат, Хэш, "НеРаспознано", "", "");
		Возврат Ложь;
	КонецЕсли;
	
	ОписаниеДанных = СтрШаблон(
		"Наименование в базе: %1.
		|Артикул в базе: %2.
		|Распознано на фото: %3",
		Кандидат.Наименование, Кандидат.Артикул, ОписаниеПоФото);
	
	СписокКатегорий = Новый СписокЗначений;
	СписокКатегорий.Добавить("Совпадает");
	СписокКатегорий.Добавить("Расхождение");
	СписокКатегорий.Добавить("НедостаточноДанных");
	
	СистемныйПромт =
	"Ты товаровед. Сравниваешь наименование карточки номенклатуры с тем, что изображено на фото товара.
	|Разный порядок слов, сокращения, регистр, отсутствие бренда в наименовании — это ""Совпадает"".
	|Другой товар, другой бренд, другая модель, другой объём или вес — это ""Расхождение"".
	|Если на фото не видно ничего, по чему можно судить о товаре, — ""НедостаточноДанных"".";
	
	МодульКлассификация = ОбщегоНазначения.ОбщийМодуль("таб_КлассификацияИКластеризация");
	Категория = МодульКлассификация.ОпределитьКатегориюПоДанным(
		ОписаниеДанных, СписокКатегорий, СистемныйПромт);
	
	Если ВРег(СокрЛП(Категория)) <> ВРег("Расхождение") Тогда
		ЗаписатьРезультат(Кандидат, Хэш, ?(ЗначениеЗаполнено(Категория), Категория, "Совпадает"),
			ОписаниеПоФото, "");
		Возврат Ложь;
	КонецЕсли;
	
	// Расхождение подтверждено — человеку нужен текст, а не «Расхождение».
	МодульНейросеть = ОбщегоНазначения.ОбщийМодуль("таб_ПрямаяИнтеграцияСНейросетями");
	Расхождение = МодульНейросеть.СделатьПромптВНейросеть(
		ОписаниеДанных + Символы.ПС + "Опиши расхождение одним-двумя предложениями, по делу.",
		"Ты товаровед, пишешь короткое пояснение для карточки задачи. Без вступлений и извинений.");
	
	ЗаписатьРезультат(Кандидат, Хэш, "Расхождение", ОписаниеПоФото, Расхождение);
	
	СоздатьЗадачуАдминистратору(Кандидат.Номенклатура, Администратор,
		СтрШаблон("Наименование не соответствует фото: %1", Кандидат.Наименование),
		СтрШаблон("%1
			|
			|Наименование в базе: %2
			|Распознано на фото: %3", Расхождение, Кандидат.Наименование, ОписаниеПоФото));
	
	Возврат Истина;
	
КонецФункции

Функция БИИДоступна(ТекстОшибки)
	
	ТекстОшибки = "";
	Модули = "таб_КомпьютерноеЗрениеИзвлечениеИнформации,таб_КлассификацияИКластеризация,таб_ПрямаяИнтеграцияСНейросетями";
	Для Каждого ИмяМодуля Из СтрРазделить(Модули, ",") Цикл
		Если Метаданные.ОбщиеМодули.Найти(ИмяМодуля) = Неопределено Тогда
			ТекстОшибки = "Не установлено расширение ТАБ:Библиотека искусственного интеллекта (нет модуля "
				+ ИмяМодуля + ").";
			Возврат Ложь;
		КонецЕсли;
	КонецЦикла;
	Возврат Истина;
	
КонецФункции

Функция БалансДостаточен(Администратор)
	
	Минимум = Константы.пфн_МинимальныйБалансСимволов.Получить();
	Если Не ЗначениеЗаполнено(Минимум) Тогда
		Минимум = 20000;
	КонецЕсли;
	
	// Имя модуля сверь в конфигураторе: в документации оно напечатано с пробелом.
	МодульВспомогательный = ОбщегоНазначения.ОбщийМодуль("таб_ВспомогательныеФункции");
	Состояние = МодульВспомогательный.ПроверитьБалансИАвторизацию();
	
	Если ЗначениеЗаполнено(Состояние.Ошибки) Тогда
		ЗаписатьВЖурнал("БИИ: " + Состояние.Ошибки, УровеньЖурналаРегистрации.Ошибка);
		СоздатьЗадачуАдминистратору(Неопределено, Администратор,
			"Не работает подключение к ТАБ:БИИ",
			"Проверка фото номенклатуры остановлена: " + Состояние.Ошибки
			+ Символы.ПС + "Личный кабинет: https://app-519908.1cmycloud.com/applications/ILLM/lk");
		Возврат Ложь;
	КонецЕсли;
	
	Если Состояние.Баланс < Минимум Тогда
		ЗаписатьВЖурнал(СтрШаблон("БИИ: остаток %1 символов меньше порога %2, прогон пропущен.",
			Состояние.Баланс, Минимум), УровеньЖурналаРегистрации.Предупреждение);
		СоздатьЗадачуАдминистратору(Неопределено, Администратор,
			"Заканчивается баланс ТАБ:БИИ",
			СтрШаблон("Остаток %1 символов. Пополните баланс в личном кабинете:
```

### Создание задачи

Реализация зависит от конфигурации. Вариант для БСП «Бизнес-процессы и задачи» —
**состав реквизитов сверь через `/meta-info БизнесПроцессы.Задание`**, он отличается по версиям:

```bsl
Процедура СоздатьЗадачуАдминистратору(Предмет, Исполнитель, Заголовок, Описание)
	
	// Не плодим дубли: если по предмету уже есть незавершённая задача — выходим.
	Если Предмет <> Неопределено И ЕстьНезавершеннаяЗадача(Предмет) Тогда
		Возврат;
	КонецЕсли;
	
	Задание = БизнесПроцессы.Задание.СоздатьБизнесПроцесс();
	Задание.Дата = ТекущаяДатаСеанса();
	Задание.Наименование = Лев(Заголовок, 150);
	Задание.Важность = Перечисления.ВариантыВажностиЗадачи.Обычная;
	Задание.Исполнитель = Исполнитель;
	Задание.Предмет = Предмет;
	Задание.ПодробноеОписание = Описание;
	Задание.Записать();
	Задание.Старт();
	
КонецПроцедуры

Функция ЕстьНезавершеннаяЗадача(Предмет)
	
	Запрос = Новый Запрос;
	Запрос.Текст =
	"ВЫБРАТЬ ПЕРВЫЕ 1
	|	Задачи.Ссылка
	|ИЗ
	|	Задача.ЗадачаИсполнителя КАК Задачи
	|ГДЕ
	|	Задачи.Предмет = &Предмет
	|	И НЕ Задачи.Выполнена";
	Запрос.УстановитьПараметр("Предмет", Предмет);
	
	Возврат Не Запрос.Выполнить().Пустой();
	
КонецФункции
```

Если подсистемы задач в конфигурации нет — заведи своим `/meta-compile` справочник
`пфн_ЗаданияАдминистратору` (реквизиты: Номенклатура, ДатаСоздания, Исполнитель, Описание,
Выполнено) и создавай элементы в нём. Логика прогона от этого не меняется — точка подмены одна,
`СоздатьЗадачуАдминистратору`.

## 5. Расписание

Расписание регламентного задания в XML метаданных не задаётся — оно живёт в самой базе.
После загрузки расширения:

```bsl
Задание = РегламентныеЗадания.НайтиПредопределенные(
	Метаданные.РегламентныеЗадания.пфн_ПроверкаНаименованийНоменклатурыПоФото)[0];
Расписание = Новый РасписаниеРегламентногоЗадания;
Расписание.ПериодПовтораДней = 1;
Расписание.ВремяНачала = Дата(1, 1, 1, 3, 0, 0);   // ночью, когда никто не работает
Задание.Расписание = Расписание;
Задание.Использование = Истина;
Задание.Записать();
```

Либо через БСП: *Администрирование — Обслуживание — Регламентные и фоновые задания*.

**Файловая база:** регламентные задания сами по себе не выполняются — нужен отдельный сеанс,
периодически вызывающий `ВыполнитьОбработкуЗаданий()`. Для отладки это не помеха: запускай метод
напрямую (см. ниже).

## 6. Тестирование

Порядок — от дешёвого к дорогому, по циклу этого скила:

1. **Без ИИ.** Проверь запрос кандидатов и чтение фото: у скольких позиций нашлось изображение,
   какого размера, читаются ли двоичные данные. Тут же залогируй сырой результат
   `ОпределитьЗначимыеРеквизитыДокумента` на одной позиции и убедись, что представления элементов
   `СписокЗначений` — это действительно переданные имена полей.
2. **Одна позиция через ИИ.** Возьми номенклатуру с заведомо правильным фото и с заведомо чужим
   (подставь фото другого товара) — должно получиться «Совпадает» и «Расхождение».
3. **Прогон целиком** в фоновом задании:

   ```bsl
   Задание = ФоновыеЗадания.Выполнить("пфн_ПроверкаФотоНоменклатурыСервер.ВыполнитьПроверку");
   Задание.ОжидатьЗавершенияВыполнения(300);
   ```

4. **Проверка состояния, а не только UI:** записи регистра `пфн_РезультатыПроверкиФотоНоменклатуры`,
   созданные задачи, журнал регистрации, расход баланса до и после.
5. **Повторный запуск подряд.** Второй прогон не должен ни тратить баланс на те же фото,
   ни создавать вторую задачу по той же позиции.
6. **Веб-клиент** (встроенный браузер, см. SKILL.md): администратор видит задачу в своём списке,
   формулировка расхождения читаемая, предмет открывается в карточку номенклатуры.

Тестовые данные и временные обработки — вне релизного расширения; в хранилище идут только
объекты из раздела 2.

## 7. Настройки и стоимость

- `пфн_МаксимумПроверокЗаПрогон` подбирается по балансу: каждая позиция — это до трёх вызовов
  модели (пригодность фото, распознавание полей, категоризация) плюс один на текст расхождения.
- Прогон ночью и небольшая порция за раз дешевле и предсказуемее, чем «проверить всё сразу».
- Первый полный прогон по большой базе лучше разбить: сначала одна товарная группа.
- Порог `пфн_МинимальныйБалансСимволов` не даёт заданию упасть в середине прогона; при его
  срабатывании администратор получает задачу со ссылкой на личный кабинет
  <https://app-519908.1cmycloud.com/applications/ILLM/lk>.

## 8. Что легко сделать дальше

  предложить корректное наименование/описание прямо в задаче.
- `таб_ПоискИнформации.НайтиПоСмыслу` — подсказать, к какой существующей позиции на самом деле
  относится фото.
- Отчёт по регистру результатов (`/skd-compile` у поставщика) — сводка расхождений по группам.
